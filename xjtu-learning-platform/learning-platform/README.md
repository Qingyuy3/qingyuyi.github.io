# 《智能商务分析与实践》在线平台

这是独立的 Cloudflare 试运行版本。旧 GitHub 公开展示页和原 Mini TA 保持不变。

## 教师使用

网址：https://xjtu-learning-pilot.pages.dev/

教师账号 `teacher`。临时密码在本机 `private/教师首次登录.txt`，不得提交到 GitHub。首次登录强制改密。

1. 教学管理 → 学生账号：从 Excel 一次复制多行账号、姓名、班级三列，表头和空行自动跳过；检查预览后批量开通，可导出 .xlsx 账号表。账号为 3–32 位字母/数字/下划线/短横线。不需要学生邮箱或自行注册。
2. 每个学生得到不同的临时密码，7 天内首次登录改密。生成页面关闭后不再显示密码；教师只能重置，不能查看学生设置的新密码。
3. 教学管理 → 发布作业：选择单元、填写要求和截止时间。时间输入采用设备时区，请将设备设为北京时间；服务器存 UTC 毫秒并统一判断是否截止。可以关闭/重新开放或修改时间。
4. 上传资料：选择单元和文件。新增文件放在私有 R2，通过已登录的平台下载；资料中心和课程内容可看到新增资料。
5. 提交与反馈：查看所有学生的版本，下载文件，填写成绩和反馈，导出 CSV 记录。CSV 可能含个人信息，妥善保存。
6. 讨论区：帖子和回复保存到 D1；刷新获取新回复；教师可以隐藏帖子及回复。

## 当前边界

- 单课程、教师和学生两类角色。没有公开注册、短信、邮件、TA 独立权限、SSO 或 MFA。
- 最大单文件 **100 MiB**，5 MiB 分块，失败分块自动重试。浏览器关闭后重新选择文件；不支持跨页面断点续传。
- 学生默认总配额 1 GiB，教师 10 GiB，全课 20 GiB；同一学生每份作业最多 5 个版本（全部保留）。每人最多 3 个进行中的上传。
- 作业提交只有 R2 文件完整验证且 D1 已记录才算成功。若网络在确认时断开，先刷新提交记录，不要反复点击。过期未完成上传可在教师页面清理。
- 上传扩展名白名单；禁止路径和控制字符；所有下载均为附件，不在网站域名下执行 HTML、脚本或 Notebook。**尚无恶意软件扫描**，下载后仍需本机安全检查，勿直接运行不可信代码。
- 小测仍为自主练习，不持久化成绩。正式成绩只来自教师保存的作业评分。
- 19 份历年材料沿用原公开静态资料，不会因为新登录系统而变成私密资料；新增资料和所有学生作业受后端权限检查保护。
- 新平台助教配额每人 20 次/UTC 日、全课 200 次/UTC 日，失败请求也计数。仍检索原目录摘要，**不会自动读取新上传文档全文或学生作业**。原公开 Mini TA 不受新平台配额约束，仍使用它原有的限制。
- 试运行期间不导入真实学生数据；先让教师试用并用校园网/手机网验证。正式教学前确认学校的数据处理要求、定期备份与维护人、文件保留期限、教师 MFA/恢复方案和安全审查。

## 文件结构

```
learning-platform/
  client.tsx / session.tsx   登录界面、账号状态
  views.tsx                 作业、讨论、教师管理、日历
  file-client.ts            浏览器分块上传
  worker.ts                 登录/权限/用户/作业/讨论/助教 API
  auth.ts / auth-options.ts Better Auth 配置（禁用注册）
  uploads.ts                私有文件、所有权、配额、提交确认
  http.ts                   请求校验、限流、安全响应
  migrations/               D1 数据库迁移；已应用的文件不要改
  wrangler.jsonc            Cloudflare Pages 云端部署
  wrangler.local.jsonc      本机模拟数据库和文件存储
  test.mjs                  接口集成测试；使用生成的测试账号
  backup.mjs                云端只读备份及本机恢复验证
  prepare-local.mjs         首次生成凭据（只运行一次）
  private/                  密码、测试结果、备份（不入 Git）
  dist/                     自动生成部署文件（不入 Git）
```

R2 文件路径：`course-001/submission/作业ID/学生ID/文件ID` 与 `course-001/material/unit-单元/教师ID/文件ID`。中文原文件名、标题、单元、提交时间保存在 D1；不依赖用户可伪造的文件夹名判断权限。

## 开发与发布

### 学生名单与账号表

教学管理 → 学生账号：从 Excel 一次复制多行“账号、姓名、班级”（班级可选），直接粘贴；支持表头、空行、制表符、逗号，以及手动空格分隔。先查看识别预览并修正错误，再确认开通。一次最多 60 人，服务器总账号上限仍为 80。前导零账号请在原 Excel 中设置为文本。

成功生成的凭据可用“导出账号表（.xlsx）”下载为标准 Excel 工作簿，可直接用 Excel 或 WPS 打开。导出时才加载 ExcelJS，不向外部服务发送凭据。所有单元格显式使用文本类型，保留前导零并防止公式执行。导出包含账号、姓名、班级、临时密码、登录网址和改密说明；密码只在页面内存中暂存，离开或刷新前务必导出。不要公开整份账号表。重置同一学生密码后，当前页面的导出列表只保留最新凭据。

部分失败时仅保留未确认成功的名单；若网络中断但服务器已经创建账号，请先核对账号列表，必要时使用该账号的重置密码功能，不要反复导入。解析与导出的维护代码在 `roster.ts`，离线回归测试为 `node learning-platform/test-roster.mjs`（不会创建真实账号）。

仓库使用 pnpm，保留锁文件。需要 Node 24。`wrangler-platform` 是独立的新版本部署工具，原 `wrangler` 保持与现有 Vinext 构建兼容。

在仓库根目录执行：
```
pnpm platform:build
pnpm platform:check
pnpm platform:dev
pnpm platform:test
```

本机开发绑定本机数据，不访问真实学生数据。首次初始化需要 `prepare-local.mjs`、本地 migrations、私有 bootstrap.sql；**不要重复向已有数据库导入 bootstrap.sql**。

生产迁移：`wrangler d1 migrations apply xjtu-learning-pilot --remote --config learning-platform/wrangler.jsonc`。

发布前先 build/check/test，再从仓库根目录执行 `node node_modules/wrangler-platform/bin/wrangler.js pages deploy dist --cwd learning-platform --project-name xjtu-learning-pilot --branch main`。正式网址必须使用上述固定主域名；临时预览子域名不在允许登录的来源中。

`AUTH_SECRET` 已通过 Pages Secret 配置；不存入仓库或前端。Pages 不支持 Worker 的 `secrets.required` 配置，类型从本地 Worker 配置生成：`wrangler types learning-platform/env.d.ts --config learning-platform/wrangler.local.jsonc --env-interface PlatformEnv`。

## 备份和恢复

### 已上传资料管理

教学管理 → 资料管理：可修改标题、所属单元，按单元、状态、上传日期及关键词筛选，并切换上传时间排序。这里只管理教师上传到平台的文件，不修改历史静态课程资源，也不删除学生作业。

- 隐藏：从学生列表移除，旧下载链接也会被拒绝；教师仍可下载检查。
- 回收站：保留文件，任何人都不能通过下载链接访问。恢复后默认为隐藏，需教师重新发布。
- 彻底删除：必须先在回收站，并输入完整文件名确认；删除私有 R2 对象，释放上传存储配额，保留数据库墓碑与审计记录。网页不能恢复，独立备份不随此操作删除。已被学生下载到本机的副本无法收回。
- 删除中断：停留在“删除未完成”，禁止恢复或下载，教师可重新确认并重试删除。版本号阻止并发恢复/删除和旧页面覆盖新修改。

`0004_material_management.sql` 是新增迁移，现有资料默认保持公开。`materials.ts` 处理教师操作，`uploads.ts` 在列表和下载处执行可见性检查。修改所属单元只更新元数据，原 R2 对象键保持不变。

离线权限与存储测试：`node learning-platform/test-materials.mjs`，使用独立、非持久化的本地 D1/R2，覆盖隐藏、恢复、真实文件删除、并发操作和删除失败重试，不操作线上资料。

仓库根目录执行 `node learning-platform/backup.mjs`。使用 Cloudflare 登录授权，不需要教师密码。导出 D1 和每个已完成 R2 文件到忽略的 `private/backups/日期/`，将 SQL 恢复到全新内存数据库并检查完整性。备份含密码哈希及学生资料，应保存到加密且受限的位置。

备份脚本**不会自动定期运行**。建议每次集中收作业后执行，并另外保存一份离机副本。R2 本身不是独立备份。

真实恢复应先新建恢复用数据库/存储桶，导入 SQL、按 manifest 的 object_key 回传文件、验证权限与下载后再切换绑定。不要直接覆盖正在使用的数据库。部署回滚不等于数据库回滚；所有后续变更以追加迁移完成。

## 验证范围

接口测试覆盖：未登录访问、跨站写入、教师与学生权限、首次改密、账号停用和密码重置撤销会话、真实分块上传/下载内容一致、100 MiB 边界、未完成上传拒绝、截止关闭、讨论跨账号回复、教师反馈。

尚未进行人工浏览器交互检查和 50 人同时交作业的压力测试；上线前应补做这些验收。保存的测试记录位于 private/，不要把测试账号发给学生。
